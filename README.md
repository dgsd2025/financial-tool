# 财务中心 · yc-finance-web

星逸平台第 9 个系统。一期范围：**系统整体结构 + 工具箱（仅 T2 银行流水转凭证可用）**。

---

## 快速启动

```bash
cd yc-finance-web
node server.js 5190
```

打开 http://localhost:5190

> 端口说明：5173 / 5180 / 5181 已被其他系统占用，默认改用 **5190**。
> 也可以不启服务器，直接双击 `index.html` 打开——所有功能都在浏览器端运行。

**零依赖**：不需要 `npm install`，没有构建步骤，只用 Node 内置模块。

## T2 的设计要点

### 支持格式
`.xlsx` / `.csv` / `.tsv` / `.txt`，UTF-8 与 **GBK 自动识别**（国内网银导出常见 GBK）。

xlsx 解析用浏览器内置的 `DecompressionStream` 实现 ZIP 解压，**不依赖任何第三方库**。

### 自动识别
- **表头定位**：银行流水前几行常是账号、户名等说明，工具扫描前 12 行按关键词密度自动定位真正的表头
- **列映射**：10 个字段各有别名表（如日期 = 交易日期 / 记账日期 / 业务日期…），自动匹配后可人工调整
- **金额形态**：支持「收入/支出双列」「发生额 + 借贷标志」「带正负号金额」三种

### 匹配规则

匹配**只看摘要**。对方户名容易误命中——例如「交通运输部」含「运输」会错配到物流费规则——所以对方户名必须由规则显式声明 `scope: 'both'` 才纳入匹配范围。

界面上每笔都显示「**匹配依据**」列，写明是靠摘要还是对方户名命中的。

### 不猜
匹配不上的一律进例外清单，**绝不猜科目**。例外可逐条人工指定，并勾选「存为规则」沉淀进规则库——**用得越久越准**。

### 输出
- **凭证导入 CSV**：15 列（日期·凭证字·凭证号·摘要·科目编码·科目名称·借方·贷方·主体·业务线·项目·合同号·对方户名·流水号·账号），自动校验借贷平衡
- **例外清单 CSV**：未匹配的单独导出，人工在账务系统处理

### 合规提示内置
主体间调拨命中时会打出警告「主体间调拨须走专用审批流」——这是方案里的最高风险项（未清账导致税务注销困难），在工具层就提示。

## 实测结果

用 `示例文件/银行流水_示例.csv`（18 笔，含 2 行说明抬头）：

| 项 | 结果 |
|---|---|
| 表头定位 | 自动跳过 2 行说明，命中第 3 行 |
| 列映射 | 8 个字段全部自动识别 |
| 匹配 | 15 / 18 = **83%** |
| 例外 | 3 笔（结息金额为 0、ETC通行费无规则、不明款项） |
| 凭证 | 15 张 / 30 行，**借贷平衡** |

例外的 3 笔都判断正确——工具没有硬猜。

## 数据与安全

- **所有解析在浏览器端完成，文件不上传任何服务器**
- 规则库与处理记录存在浏览器 `localStorage`
- 服务器只做静态文件分发，不接收、不存储任何业务数据

> ⚠️ localStorage 是浏览器本地存储，换电脑/清缓存会丢。接入平台后应改为服务端存储——这也是接入时要做的第一件事。

## 下一步

按「跑完一个再做下一个」的原则：

1. **让出纳用 T2 处理一次真实的月度流水** — 这是真正的验收
2. 观察真实匹配率，把例外沉淀成规则
3. 规则库养到匹配率稳定 90% 以上，再开 **T3 对账单核对器**

真实流水跑一遍会暴露示例文件覆盖不到的问题：各家银行的导出格式差异、摘要写法习惯、特殊业务类型。**这些正是规则库要吃进去的东西。**
